# Patronage

Cozy Renaissance-Italy city builder. Full design spec: docs/design-doc.md — read it before implementing any game system (resources, commissions, buildings, worker allocation, artists, etc.). The prioritized backlog lives in docs/roadmap.md.

## Non-negotiable design constraints

From the doc's "Key Design Principles" — flag it if a change would violate one of these rather than just implementing it:

- No citizen pathfinding, no granular supply chains — service buildings are threshold checks, not simulations. Materials **are** an accumulating stockpile since July 2026 (a deliberate reversal): three city-wide pools that staffed suppliers fill per tick and commissions spend lump-sum at assign. Still no routing, no per-building stores, no mid-work stalls — and materials stay off the top bar.
- All art is commissioned (once Phase 8 lands): every artwork has a requester, a name, and stakes. Requesters (Church, noble families) carry a 0–100 favor meter moved only by player decisions — completions up, declined/expired offers down, **never time decay**. Consequences stay faction-scoped (that faction's offer rate and grandeur), with one sanctioned exception: a first slide into Affronted fires a one-time denunciation prestige hit. Favor is never a top-bar resource.
- Exactly 3 headline resources (Florins, Inspiration, Prestige) + Population as status. Don't add a new top-bar resource without a real player decision behind it.
- Every building either unlocks something or passively boosts something — never requires active management.
- Spatial effects are soft: plaza proximity is a flat bonus, never a hard in/out radius.
- Renaissance = prestige milestone soft ending; play continues afterward.

- When a roadmap item ships, delete its entry from docs/roadmap.md and document the built system in the design doc, marked *(built)*. Update docs/artifacts/game-mechanics-audit.md in the same change: its Part 1 mechanic rows and Part 2 built/not-built status must track every completed feature. 
- Commit messages are one line, written in a technical register: lowercase, terse imperative, no conventional-commit prefixes. Add a body only when the change genuinely can't be understood without one — the docs carry the reasoning, not the git log.

Factions slice 1 (July 2026): the requester pool is now gated by patron admission (`requesterPool` in `app/game/art/commissions.ts` — Chapel or Cathedral seats the Church, each Palazzo installs the next noble house in table order; guild requesters removed) and each patron carries persisted 0–100 favor (`favor` in the store; reads default `FAVOR_START` 50; save v8 seeds old saves from per-requester completed works). Material stockpiles (July 2026): the supplier capacity-token model was replaced by accumulating stock (deliberate reversal of "materials are never a stockpile" — see the constraint bullet above). `app/game/art/materials.ts` lost the whole allocation engine (`computeSupply`/`getSupply`/`assignedMaterials`/`blockedReason`/`MaterialSupply`) and now holds pool math only: `materialCaps(tiles)` (`MATERIAL_STORAGE_BASE` 20 + each supplier's `storage` for its own material + each Warehouse's `materialStorage` 50 for all three — storage counts unstaffed, only production needs workers) and `addProduction` (clamp-and-add, identity-stable). Architects slice 1 (July 2026): the third discipline landed as a construction pipeline. **Materials grew to five pools** — timber + stone join pigment/marble/bronze (`Material` union in `types.ts`, `MATERIALS` in `materials.ts` drives caps/production/panel rows automatically; save v10 seeds the new keys), produced by two new suppliers (**Timber Yard**, **Stone Quarry** — marble-supplier stat clones). **Grand buildings cost construction materials** at placement: `BuildingMetadata.buildCost` on cathedral (40 stone + 10 timber — one full quarry ceiling), palazzo, bell tower, warehouse; checked in `planPlacement`/`canPlaceAt` (`PlacementSnapshot` gained required `materials` + optional `fundedBuilds`; `PlacementPlan.materialCost` is the batch bill placeTiles deducts), lump-sum like commission stock — houses/roads/workshops/suppliers stay florins-only (no bootstrap deadlock), salvage stays florins-only, the palette shows the bill and dims on shortfall (the red ghost rides `canPlaceAt`; `demoLayout.check.ts` + demo boot pass Infinity pools). **Architect's Studio** (`architect_studio`, workshop stats, `artistType: "architect"`, no chimney → no smoke, no display slots) spawns architects into the existing generic machinery. **The city teaches architects**: `placeTiles` calls `trainOnConstruction` (`artists.ts`) against pre-placement state — every architect in an active studio gains `XP_RATES.perFlorinBuilt` (0.05) × florins actually spent (cathedral = 75 XP; fences floor to 0; funded 0ƒ builds teach 0). **Every architect offer is a blueprint commission**: `maybeOfferCommission` swaps the title draw for a `BUILDING_COMMISSIONS` pick (same single rng call — painter/sculptor draw order untouched), Church → **Baptistery** (prestigeOnBuild 40, church display host), nobles → **Loggia** (2 plinth slots, inspiration 2); `Commission.building` marks it, no materialCost stamps (design work is free to assign). Completion mints the design as a normal Artwork (favor +8, Renaissance gates, gallery all ride the standard path — `SLOT_KINDS_BY_ARTIST.architect = []` keeps designs undisplayable) and the tick appends the id to persisted `fundedBuilds`. Both structures are `commissionOnly: true`: hidden from the palette until funded ("Funded" badge, no florin price), placeable exactly once per token at 0ƒ + their `buildCost` (baptistery 30 stone — held against the stores), token consumed in `placeTiles`, salvage 0, no refund on raze-reopen. Deferred: rank-gating (`minRank`), Town Hall/Dome-tier asks, a civic Commune requester, distinct studio/loggia/baptistery models (placeholders ship: workshop hall minus dormer + drafting yard; arch-bay arcade under a hip; square drum + portal + lantern standing in for the octagon).

Layout: `app/game/` = sim logic, `app/game/render/` = Babylon rendering, `app/game/ui/` = DOM overlay UI, `app/stores/useGameStore.ts` = Zustand store. Check there before assuming a system exists.

## Code organization

- Sim modules live in feature subdirs of `app/game/`: `placement/` (placementRules, raze, roadSnap, roadStretch), `art/` (artists, commissions, display, renaissance, materials), `city/` (connectivity, workers, metrics, traffic, crowd), `map/` (seed, water), `audio/`, `demo/`. Root holds only shared foundation imported by 3+ clusters (`types`, `constants`, `random`, `buildings`, `grid`) plus the orchestrators (`tick`, `saveMigration`, `checkHelpers`). New features go in the matching subdir, `.check.ts` colocated (the test glob is recursive).
- UI: one component file = one concern. Split when a file grows a second unrelated state cluster or an inline dropdown/submenu/tooltip beyond a few lines — `GameHUD.tsx` is the composition-root model (TopBar → SettingsMenu/TopBarStats is the precedent). Markup repeated in 2+ panels gets extracted (`ArtworkRow`, `CommissionMeta`); pure data like icon/label maps lives in data modules (`buildingIcons.ts`, `labels.ts`, `ARCHETYPE_LABELS` in water.ts), never inside a component file.
- Reuse before writing. Check for an existing helper/component before implementing one in place: sim math surfaced in UI calls the sim's own function so tooltip and tick can't drift (`plazaBoost`/`trafficFactor` in `city/traffic.ts`, `supplierRate` in `city/metrics.ts`, `applyFavor` in `art/commissions.ts`, `origins()` in `buildings.ts` for scan-all-buildings loops); panel chrome comes from the shared primitives in `Panel.tsx` (`Panel`, `HudPanel`, `HudToggleButton`, `CloseButton`, `Row`, `ModalBackdrop`) plus `ResourceStat` (tooltip-capable) and `ui/format.ts`. Hand-copying any of these is how the July 2026 dedup pass found ~700 lines of drift-prone duplicates.
